# HX Effects preset builder

A page for building HX Effects presets and sending them straight to the unit over USB: pick blocks, set their knobs,
route two paths, set up snapshots, footswitches and controllers. HX Effects only.

## Where the models come from

Every model, knob, range and setting name comes from **`fw-catalog.js`**: the model tables extracted from Line 6's
HX Effects 3.80 firmware and from this repo's three builds of it (each model's preset id, block type, DSP cost,
category, legacy flag and name; each knob's name, range, default, display type and choice names). It is our own data
file, generated by `make_catalog.js`; no Line 6 file or code is in this repository or on the website. The page needs
no firmware file. Regenerate it after a recipe changes (it needs the stock file in `firmware/` and only Node):

```bash
node tools/preset-builder/make_catalog.js
```

`fw-reader.js` reads the firmware's model tables (a JavaScript port of `tools/preset_send.py model_table()`, giving
the same tables); `make_catalog.js` runs it on the stock file and on each build the setup page's recipes make, and
checks it is the stock 3.80 file. Without `fw-catalog.js` the page falls back to asking for the firmware file and
reading it in the browser. (`extract_fw_tables.py` writes `fw-models.js` from the images in `build/` for the
Python/JavaScript cross-check, `check_core.py`; git-ignored.)

The **Your unit runs** menu picks which of this repo's builds is on the unit (`build.py`), and the model list follows it.
The page can't check it: the unit reports the same version and build id on every build, and nothing over USB lists its
models. So **Send** shows a warning naming the build the preset is made for (and any models only this repo's
firmware has), and won't send until "My HX Effects runs the …" is ticked. **If a preset locks up the unit**, at the top of the page under the header, gives
the recovery steps (power cycle; FS4 + FS5 held at power-on starts on 1A with Global Settings reset, presets kept;
then replace the bad slot without loading it):

| Firmware | Adds |
|---|---|
| Stock 3.80 firmware | nothing: HX Effects' own models |
| NAM firmware | NAM A2 Lite (on mono Regal Bass DI) and Click (on mono Mod/Chorus Echo) |
| NAM + Amps firmware | the HX Stomp's 111 amps (Amp) and 112 preamps (Preamp), at most three per preset |
| NAM + Amps + Effects firmware | the effects a plain `build_all.py` makes (Bolt, Rocket!, Garrrry Tank, Quality Polis, Bam Crusher, ...) and the HX Stomp's 41 legacy cabs (Cab), at most two per preset |

A cab block stores its **Mic** after its five knobs, as 0..15 in the unit's order (57 Dynamic ... 7 Dynamic; the page
lists the names), counted in the value list's length but not in its knob count: `{2: 6, 3: 5, 4: [Distance, Low Cut,
High Cut, Early Reflections, Level, mic]}`, as a preset saved on the unit stores it. `preset-core.js` and
`tools/preset_send.py` both write it that way (`check_core.py` agrees on 400 random presets).

The cabs are listed under their names in the unit's Cabs menu (`CAB_MENU_NAMES` in `real-names.js`, from
`tools/cab_list.py`): the firmware's model data names 1x12 Cali IV, 1x12 Cali EXT and both Del Sols "4x12 SoloLead EM".

**Real names** (the box next to the firmware picker): for firmware built with real names (`build.py --real-names`,
or the setup page's Real names box), the page shows the same names as the unit, e.g. OrangeRockerverb for Mandarin
Rocker. Search finds a model by either name. Presets are the same either way. The names come from `real-names.js`,
written by `python tools/real_names.py --js` from the table in `tools/real_names.py`: don't edit it by hand.

Under the categories, **All / Mono / Stereo / Legacy** filter the list the way the unit's browser files models: Legacy
holds the older Line 6 models (the firmware's own `legacy` flag), Mono and Stereo the rest, and a model picked from
Mono or Stereo goes in as that version. Models added by a build are marked ★. DSP load is the firmware's own cost for each model, 75 units to 1%
(measured on the unit: a preset over about 7,500 units loads with nothing running); the page
refuses a block that would take the preset over 100%, or a fourth amp/preamp.

Seven of the custom effects are **overlays**: Bam Crusher, Doom Chug, Pure Whitey, Greasy Strangler, Drum Chapel,
Bethblahem and Puggy Puncher share one code region. One on its own costs only its own load. With two or more in a preset,
the unit copies each one in every time it runs, so the page adds 20% per overlay. A preset with five of them froze the
unit. Two heavy ones (Drum Chapel + Bam Crusher + a reverb, 95%) and three light ones (Doom Chug + Puggy Puncher +
Bethblahem, 99%) were tested on the unit and play fine with the knobs turning.

## Running it locally

```bash
python3 -m http.server 8767 --bind 127.0.0.1                    # from the repo root: the page loads ../../web/*
```

Then open <http://127.0.0.1:8767/tools/preset-builder/> in Chrome or Edge. On the website the page sits in
`preset-builder/`, beside the setup page's `flasher.js`, `firmware-core.js` and recipes.

## Sending to the unit

**Send to unit** writes the preset straight into a slot over USB (WebUSB: Chrome or Edge, HX Edit and Line 6 Updater
closed), the way `tools/preset_send.py build` does, with `preset-core.js` (the same bytes: `check_core.py`). Every knob
reaches the unit, custom effects' own knobs included; it reads the slot back to check it (the unit now and then stores a
write with its start scrambled: the page writes again, and never loads a copy that differs), and can load it. **Open from unit**
lists the unit's 128 slots by bank, with the loaded one marked: click a preset to open it in the page and switch the
unit to it (untick "Switch the unit to it too" to only open it). Send then offers that slot. It asks before replacing
edits that haven't been sent or saved. Footswitch LEDs are stored as the unit stores them: the block's colour, lit
while the block is on and dim while it is off. Everything below travels both ways:
- **Two paths**: path A and path B (the lower path), nine blocks each; drag blocks between them. Split and Merge set
  where path B leaves and rejoins path A: drag the two points on the diagram (or use the dropdowns). Click a point
  for its settings: the split's Balance A/B, and the merge's A/B Level and Pan, B Polarity and output Level.
- **Snapshots**: the four snapshot buttons above the chain pick the one you're editing (and the one the unit opens
  on); rename it in the box next to them. A block's On/Bypassed is per snapshot. Turn **Snapshot bypass** off on a
  block to keep it the same in every snapshot.
- **Footswitch** and **MIDI bypass CC** per block (several blocks may share a footswitch).
- **Knob controllers**: under each knob, Fixed, Snapshots (a value per snapshot: set it with the knob in each
  snapshot), EXP 1/2, FS1–6 (switches between Min and Max) or MIDI CC (with Min and Max).
- **IR blocks** list the IRs on the unit by name (read over USB).

**Save / Open** keep all of the above in a `.json` file. **Export .hlx** writes an HX Edit preset file (blocks, both
paths, split and merge settings, snapshot names; not snapshot states or controllers), and **Open** also takes an
`.hlx`. The .hlx frame is written by the page; blocks carry the firmware's model and knob names, which are HX Edit's.
A custom effect goes into an .hlx as the stock block it took over (mono), with its own knob values.
